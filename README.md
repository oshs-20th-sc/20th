# 행사 웹사이트

GitHub Pages + Firebase. 학생 화면은 HTML·CSS·JavaScript를 직접 수정하며 설치·빌드 과정이 없습니다.

- `typing/`: 학생 타자 대회. 관리자 `/typing/admin/`.
- `write/`: 학생 글 작성. 관리자 `/write/admin/`.
- `welcome/`: 승인된 공개 글 조회. 로그인 불필요. 관리자 `/welcome/admin/`.
- `db/`: Firebase 연결·DB 작업·학생 관리·공개 설정·보안 규칙·인덱스·관리 도구. 명부 자체는 포함하지 않습니다.

루트 `index.html`은 개발용 링크 모음입니다. 공통 파일은 루트에 둡니다. 루트 파일은 `.gitignore`의 허용 목록으로 관리하므로 새 진입 파일도 추적 예외가 필요합니다.

`db/public.js`는 공개 글·행사 설정의 읽기 전용 모듈입니다. `welcome/`은 관리자 CRUD·타자 채점 코드를 불러오지 않습니다.

관리자 진입·로그인·탭 이동은 `admin.js`에 둡니다. 화면 코드는 `admin/letters.js`(글), `admin/typing.js`(타자 기록), `admin/students.js`(학생·이력), `admin/settings.js`(운영·문구), `admin/account.js`(관리자 계정)로 나눕니다. `admin/state.js`는 세션과 화면 상태, `admin/shared.js`는 공통 폼·캐시·작업 처리를 담당합니다. 기능 모듈은 스스로 화면이나 인증을 시작하지 않으며 진입점에서 연결합니다. DB 조회·저장은 계속 `db/`에서 관리합니다.

Firebase 명령은 `db/`에서 실행하거나, 저장소 루트에서 `--config db/firebase.json`을 지정합니다. 운영 프로젝트는 명시적으로 선택합니다.

```text
firebase deploy --config db/firebase.json --project os20th --only firestore:rules,firestore:indexes
```

디자인은 `style.css`의 공통 색·테두리 변수와 기본 요소 스타일에서 조정합니다. 타자 입력 표시는 `typing/style.css`에 둡니다. 프레임워크·아이콘·외부 폰트 의존성은 없습니다.

| 파일                                                                  | 용도                                                    |
| --------------------------------------------------------------------- | ------------------------------------------------------- |
| `db/firebase.js`                                                      | 학생·관리자 인증, Firebase 연결, 세션 정책              |
| `login.js`                                                            | 타자 참가용 학번·이름 입력과 초기화                    |
| `db/database.js`                                                      | 글·타자 접수, 검증, 검수·공개, 내보내기                 |
| `admin.js`, `db/students.js`                                          | 관리자 화면과 학생 검색·제한·관리 기록                  |
| `common.js`, `style.css`                                              | 공통 함수·스타일                                        |
| `db/firebase-config.json`                                             | 공개 웹 SDK 설정                                        |
| `db/firestore.rules`, `db/firestore.indexes.json`, `db/firebase.json` | 보안 규칙·인덱스·배포 설정                              |
| `db/scripts/import-students.mjs`                                      | 서버 Admin SDK를 사용하는 멱등 학생 일괄 등록           |
| `db/scripts/restore-backup.mjs`                                       | 비공개 DB 백업 검사·누락 문서 복원                      |
| `db/scripts/functions/`                                               | 관리자 전용 비밀번호 재발급 서버. 운영 연결은 현재 보류 |

로컬 실행: Node 24 이상에서 `node serve.mjs`. `/typing/`, `/write/`, `/welcome/`으로 접속합니다. `?emulator=1`은 localhost 또는 127.0.0.1에서만 에뮬레이터에 연결하며 기기 보호 정책을 바꾸지 않습니다.

학생은 현재 5자리 학번과 이름을 직접 입력합니다. 이는 참가 정보 기록이며 실제 본인 여부를 인증하지 않습니다. 학생 회원가입·비밀번호·Google OAuth·익명 Auth·기존 명부 조회는 사용하지 않습니다. `/typing/`은 기존 로그인 화면에서 참가 정보를 입력한 뒤 타자 화면으로 이동합니다. `/write/`는 로그인 없이 학번·이름·별명·본문·공개 동의를 입력하고 제출합니다. 학생 화면은 인증을 초기화하지 않는 공개 DB 연결을 사용하고, 관리자 Firebase Authentication과 `admins/{uid}.enabled` 권한 검사는 유지합니다.

새 기록은 `entry_mode: 'record'`, `owner_uid: null`로 기존 UID 기록과 구분합니다. 타자는 `participantId`(학번)·`displayName`(이름), 글은 관리자 전용 `student_number`·`student_name`에 입력값을 저장합니다. 기존 Auth 계정·`students/{uid}` 명부·UID 기반 글·타자 기록은 삭제하거나 새 학번에 자동 귀속하지 않습니다. 기존 계정 관리·이력과 관리자 복구 도구는 과거 자료를 위해 보존합니다.

행사는 2026년 11월 23일(월) 점심시간 현장 참여로 운영합니다. 정확한 점심시간은 코드에 넣지 않습니다. 운영진이 기존 관리자 접수 설정으로 현장 점심시간에만 타자·글 접수를 열고 마칩니다. 접수 시간 외에는 닫아 두어야 합니다. 서버 규칙은 접수 활성화 상태를 확인하지만 브라우저의 물리적 현장 위치나 점심시간 자체를 증명하지 않습니다.

공식 타자는 행사 전체에서 학번당 한 번 접수합니다. 결과·접수 확인 정보·`receipts/official-20261123-<학번>` 참여 키를 같은 원자적 작업으로 생성하여 다른 기기나 다른 공식 문구의 중복 저장도 제한합니다. 연습에는 공식 참여 키를 쓰지 않습니다. 같은 UUID·같은 내용의 저장 재시도는 기존 접수로 처리하며 새 참여로 세지 않습니다. 관리자 복구로 중복을 보존한 경우 원본 기록을 표시하고, 같은 페이지의 동일 학번도 구분합니다. 과거 기록의 점수는 자동으로 수정하거나 재계산하지 않습니다.

글 주제와 학생당 제출 수에는 제한이 없습니다. 본문은 비어 있지 않아야 하며 기존 10~700자 제한은 없앴습니다. Firestore의 1 MiB 문서 한도와 변경 이력의 전후 사본을 고려해 본문·공개용 본문 각각 UTF-8 128 KiB까지 저장합니다. 제출한 글을 학생이 조회·수정·삭제할 수 없으며 새 UUID로 새 글을 제출할 수 있습니다. 새 글은 `pending`으로 접수하고 욕설·비방·허위사실·개인정보·중복은 운영진이 검수합니다. 공개 글과 `welcome/letters.json`에는 승인된 본문·별명 등 기존 공개 필드만 포함하며 학번·이름·내부 소유자·참여 키는 포함하지 않습니다.

관리자 학생 탭은 기존 계정과 관리 이력을 확인하기 위해 보존합니다. 기존 계정의 활성·작성 제한 설정은 명부 조회를 하지 않는 새 참가 정보 입력 방식에 적용되지 않습니다. 새 글은 관리자 목록에서 입력 학번·이름으로 식별하고, 기존 UID 기록은 이전 명부·관리 이력 연결을 유지합니다.

관리자 글·타자 목록은 DB 커서로 다음 페이지를 읽습니다. 글은 20건, 타자는 25건 단위입니다. 타자 순위는 선택한 문구·확인 상태 전체를 기준으로 계산하고 페이지를 넘겨도 순위·동점·학생별 최고 기록 기준을 유지합니다. 전체 시도는 접수 최신순입니다. 본문·이름 검색은 DB에서 읽은 후보를 확인하므로 검색 조건에 따라 추가 페이지를 읽을 수 있습니다. 전체 조회는 명시적인 CSV·JSON 내보내기·백업·공개 내용 동기화에서 사용합니다.

글 목록에서 개별·선택 승인 및 제외가 가능합니다. 일괄 검수는 글별로 원문·공개 내용·이력을 함께 저장하며, 일부 실패하면 완료 건수를 알립니다. 삭제는 `letterTrash`로 이동하고 공개 내용은 즉시 제거합니다. 복원은 검토 대기로 돌아가며, 영구 삭제는 휴지통에서만 가능합니다. 접수 키와 변경 이력은 삭제하지 않습니다. `letterLogs`는 관리자 추가·수정·검수·휴지통 이동·복원·영구 삭제의 담당자·시각·변경 전후 내용을 보관하며 수정·삭제할 수 없습니다. 글별 이력과 전체 변경 이력에서 조회합니다. 기존 글은 소급 이력을 만들지 않습니다.

학생 탭에는 학번 연결·미연결 인원과 미연결 필터가 있습니다. 글·타자 목록은 현재 페이지 작성자의 학생 문서만 중복 없이 조회하고, 학생 관리 탭과 전체 CSV 내보내기에서 전체 명부를 읽습니다. 5자리 학번 검색은 인덱스로 조회하며 1~4자리 부분 학번 검색을 명시적으로 실행한 경우에는 기존 부분 일치 기능을 위해 전체 명부를 읽을 수 있습니다. 관리자 명부는 같은 세션에서 1분간 메모리에 재사용합니다.

글·타자 목록은 검색 조건·페이지별로 최대 10개, 60초간 메모리에 보관합니다. 캐시를 보여주기 전에도 관리자 권한은 다시 확인합니다. 저장·제재·새로고침과 로그아웃·계정 전환·권한 해제 시 관련 캐시를 비웁니다. 편집창은 해당 문서를 다시 읽어 최신 값으로 엽니다. 관리자 권한 해제는 실시간으로 반영합니다. 공개 `welcome/`은 인증 SDK나 로그인 세션을 초기화하지 않고 공개 DB만 연결합니다.

학생 상세의 작성 글·관리 기록은 각각 최신 20건부터 커서로 조회하고 더 보기로 이어 읽습니다. 목록 밖의 관련 글을 선택해 진입하면 소유자를 확인한 해당 문서 한 건만 추가 조회합니다. 학생 조치 폼도 명부의 최신 상태를 확인한 뒤 표시합니다.

학생 제출은 공개 연결에서 새 문서 생성만 허용합니다. 규칙에서 학번·이름의 형식, 접수 상태, `pending` 검수 상태, 미수령 상태, 타수·3점 감점 계산식, 공식 참여 키를 확인합니다. 원문·타자 결과·명부·관리자 역할·이력은 일반 학생이 임의로 읽거나 변경할 수 없습니다. 알려진 UUID의 새 방식 접수 확인 정보는 이름·학번·본문이 없는 해시·종류·시각만 읽어 응답 유실 재시도를 처리합니다. 공식 참여 키는 관리자만 조회하며 학생은 기존 키를 수정·삭제할 수 없습니다. 과거 계정용 생성 경로로 새 참여 제한을 우회할 수 없도록 일반 학생의 기존 UID 방식 생성은 막습니다.

본인 인증과 신뢰할 서버 측 측정이 없으므로 사칭, 다른 학번을 사용한 반복 접수, 자동 요청·할당량 소진, 거짓 소요 시간·오타를 넣어 계산식을 만족시키는 조작은 완전히 막을 수 없습니다. 공식 순위·상품은 운영진의 현장 확인과 관리자 검수로 확정해야 합니다. 추가 서버·Cloud Functions·유료 요금제는 사용하지 않습니다.

일괄 검수는 관리자 확인을 작업당 한 번 수행하고 글별 트랜잭션으로 처리하며, 저장 후 글별 추가 조회는 하지 않습니다. 이미 같은 검수 상태인 글은 쓰기와 이력 생성을 건너뜁니다. 공개 내용 동기화는 원본과 기존 공개 목록을 비교하여 바뀐 내용·누락·불필요한 공개 문서만 쓰거나 지웁니다.

`welcome/`은 20개씩 읽는 목록, 글 상세, 공유 링크와 새로고침을 제공합니다. 실시간 모드에서는 5페이지까지 60초간 메모리에 보관하고, 페이지 이동·상세 열기·브라우저 뒤로 돌아오기마다 공개 설정을 다시 확인합니다. 공개가 닫히거나 조회에 실패하면 화면과 캐시를 비웁니다. 캐시에는 공개 글만 보관하며 기기에 영구 저장하지 않습니다. 실시간 모드에서는 전체 본문 검색을 위해 DB 전체를 가져오지 않습니다.

입학식용 정적 배포는 선택 사항입니다.

1. 글 관리자에서 검수를 마친 뒤 **입학식용 letters.json**을 내려받습니다. 공개용 문서의 ID·별명·본문·순서만 포함하며 원문·학생 UID·제재·관리 이력은 포함하지 않습니다.
2. 파일을 `welcome/letters.json`으로 넣고 커밋·푸시합니다. `/welcome/`은 이 파일을 우선 사용하며 Firebase SDK와 DB를 연결하지 않습니다. 검색·페이지 이동·상세·공유는 내려받은 데이터 안에서 처리합니다.
3. 내용을 바꾸려면 다시 내보내고 배포합니다. 파일을 제거하고 재배포하면 DB 연동으로 돌아갑니다. 정적 파일이 있는 동안에는 DB의 공개 스위치가 이 파일을 닫지 않으므로, 공개 중단도 파일을 제거하거나 빈 공개본으로 교체한 뒤 배포해야 합니다.

정적 공개본은 기존 `schemaVersion: 1` 형식을 사용하며 10MB 이하입니다. 파일이 없을 때(404)만 DB로 연결하고, 형식 오류·실패 응답은 오류로 표시합니다. 공개 JSON 내보내기는 원본 글 전체 대신 `publicLetters`만 읽습니다. 현재 저장소에는 정적 공개본을 포함하지 않아 DB 연동이 기본입니다.

`settings/sessionPolicy`는 관리자 설정에서 관리합니다. 없으면 공용 기기 모드·미사용 10분·2026학년도를 적용합니다. 타자 참가 정보는 현재 페이지 메모리에서만 보관하며 새로고침 후 복원하지 않습니다. 타자 진행·저장 중에는 미사용 자동 퇴장을 미룹니다. 저장이 확인되면 화면과 메모리에서 학번·이름을 비우고 다음 참가자 버튼을 표시하며, 새 방식의 성공 기록은 기기 보관함에서도 정리합니다. 실패 기록과 기존 기기 백업은 관리자 복구를 위해 보존합니다. 공용 기기를 학생에게 넘기기 전에는 관리자 페이지에서 반드시 로그아웃합니다.

글 저장 결과가 확인되지 않으면 같은 접수 번호와 내용을 유지해 재시도합니다. 재시도 중에는 입력을 잠가 다른 사람의 이름이나 본문으로 기존 접수를 바꾸지 않습니다. 성공하면 모든 입력을 비우고 새 글 버튼을 제공합니다. 직접 초기화할 때 확인되지 않은 접수가 있으면 경고하며 새 UUID로 돌아갑니다.

모든 타자 시도는 보관합니다. 문구·연습/공식별 학번당 최고 기록 하나에 순위를 매기며 점수 → 오타 → 소요 시간으로 비교합니다. 완전 동점인 같은 학생의 시도는 먼저 완료한 것을 대표로 선택합니다. 제외 기록은 순위에 반영하지 않습니다. 관리자 보기에서 최고 기록·전체 시도를 전환하고 CSV도 선택한 보기를 따릅니다. 전체 JSON은 모든 기록을 보관합니다. 시작·중단·다시 하기 버튼은 없습니다. 로그인 후 문구를 불러오면 첫 입력부터 측정합니다. 분당 타수는 글자 수가 아니라 두벌식 키 입력 수를 기준으로 계산합니다.

새 행사 참가 기록은 오타당 3점으로 고정합니다. 기존 문구에 `errorPenalty`가 없거나 예전 값이 있어도 학생 화면·새 기록 계산·규칙 검증·관리자 새 기록 미리보기는 3점을 사용합니다. 과거 문구별 설정 필드는 보존하고 감점 필드가 없으면 3점으로 읽습니다. 제목·본문·연습 여부 등의 수정은 기존 `challenges/{id}`를 그대로 업데이트하며 본문의 기준 타수는 `countKeystrokes()`로 계산합니다. 저장 후 DB에서 다시 읽어 관리자 화면에 반영합니다. 과거 타자 기록의 점수는 자동 재계산하지 않으며 검수·상품 상태만 바꿀 때도 유지합니다.

새 행사 점수는 `max(0, round(referenceKeystrokes × 60000 / elapsedMs) - errors × 3)`이며 학생 화면, 관리자 새 기록 미리보기, 접수 검증과 보안 규칙에서 같은 계산식을 사용합니다. 새 학생 제출 권한은 정적 파일과 함께 `db/firestore.rules`를 배포해야 적용됩니다.

타자 문구에는 휴지통·복원 기능이 없습니다. 사용 중인 문구는 다른 문구로 바꾼 뒤 영구 삭제할 수 있습니다. 문구 삭제는 `challenges/{id}` 한 문서만 삭제하며 기존 타자 기록은 남깁니다. 삭제된 문구의 기록은 전체 문구·전체 시도에서 조회하고 확인·상품 수령 상태는 변경할 수 있지만, 문구가 없으므로 점수·시간·참가 정보 수정이나 새 접수는 허용하지 않습니다. 전체 문구 CSV에는 서로 다른 문구를 합친 순위를 표시하지 않습니다. 예전 삭제 보관 문서는 자동 삭제·복원하지 않습니다. 글 휴지통은 별도 기능으로 유지합니다.

학생 일괄 등록은 공개 웹사이트에서 실행하지 않습니다. `firebase-admin`은 별도 개발 환경에 설치하고, 명부·자격 증명·결과 보고서는 저장소 밖에 둡니다. 비공개 입력은 `uid`(무작위 20자리), `admission_id`(입학번호), `student_name`, `admission_year`, 선택적인 `login_id`로 구성합니다. `uid`는 최초 준비 시 한 번 생성하고 재시도에도 같은 값을 사용합니다. 입학번호는 Auth 최초 비밀번호를 설정할 때만 사용하고 학생 문서·결과 보고서에 복사하지 않습니다. 도구는 입력 전체의 중복·형식·관리자 충돌을 검사하고 기본값으로 읽기 전용 검증을 수행합니다.

```text
node db/scripts/import-students.mjs --input PRIVATE_ROSTER.json --project PROJECT_ID --dry-run --admin-module-dir EXTERNAL_NODE_MODULES --report PRIVATE_REPORT.json
```

검토한 명부에 `--apply`를 명시해야 계정을 생성합니다. `--only 현재학번` 또는 `--only 내부UID`로 개별 재시도할 수 있으며 `--concurrency`는 기본 5, 범위 1~10입니다. Auth 생성 후 Firestore 생성이 실패한 경우 다음 실행에서 학생 문서만 복구합니다. 기존 계정 비밀번호·제재 상태·관리자 계정은 변경하지 않습니다. 현재 학번 연결은 `db/scripts/link-student-logins.mjs`에서 비공개 `{student_id: 내부UID, login_id: 현재학번}` 연결표와 `--academic-year`를 사용합니다. 중복·학년·기존 계정·번호 충돌을 전체 사전 검사한 후 `--apply`로 이메일과 로그인 번호만 연결합니다. UID·이름·비밀번호·제재 상태·기존 기록은 유지하고, Auth와 명부 사이의 부분 실패는 재실행으로 복구합니다. 기존 명부 등록 스크립트도 이미 연결된 로그인 번호를 보존합니다. 공개 로그인 번호 조회 컬렉션은 만들지 않습니다.

기본 인증은 Admin SDK의 Application Default Credentials이며, `--credential-module`로 저장소 밖의 자격 증명 모듈을 지정할 수 있습니다. 보고서에는 진행·오류를 남기고 비밀번호는 기록하지 않습니다.

기존 관리자 비밀번호 재설정은 Firebase 기본 이메일 링크를 사용합니다. 학생 비밀번호 재발급은 서버 Admin SDK가 필요합니다. `db/scripts/functions`는 관리자 권한을 확인하고 임시 비밀번호를 한 번만 반환하며 비밀번호를 로그·Firestore에 남기지 않습니다. 현재 무료 요금제 유지 방침에 따라 운영 배포는 보류했고 `studentAdminFunctionsEnabled`를 활성화하지 않습니다. 향후 서버 배포가 완료된 경우에만 이 공개 설정을 `true`로 바꿉니다. Functions 지역을 바꾸면 서버 `STUDENT_FUNCTION_REGION`과 클라이언트 `functionsRegion`을 같이 설정합니다. 학생 상태 관리에는 서버 함수가 필요하지 않습니다.

GitHub Pages는 `main` 브랜치 루트를 직접 배포하며 푸시하면 반영됩니다. 다른 레포·도메인으로 옮길 때 파일의 상대적인 구조를 유지하면 경로가 따라갑니다.

- `CNAME`은 임시 배포 전용이므로 새 저장소에서는 제거하거나 새 도메인으로 바꿉니다.
- 새 저장소의 Pages를 활성화하고 Firebase Authentication의 승인된 도메인에 새 호스트를 등록합니다.
- 같은 Firebase 프로젝트를 사용하면 기존 Auth 계정·DB·SDK 설정을 그대로 유지합니다. 다른 Firebase 프로젝트로 바꾸는 경우 Auth·DB 이전과 공개 SDK 설정 교체가 별도로 필요합니다.
- 보안 규칙은 대상 Firebase에 배포해야 적용됩니다. 익명 인증의 활성 여부와 관계없이 새 학생 제출은 규칙에서 차단합니다.

관리자 글 목록에는 작성 계정이 표시되며, 해당 학생 관리 화면으로 이동하면 문제 글이 관련 글로 선택됩니다. 이 정보는 공개 글에 포함되지 않습니다.

타자 기록의 서버 접수에 실패하면 기기 보관함에 남깁니다. 기기 보관도 실패했을 때만 기록 파일 저장 버튼을 표시하고, 파일 저장을 확인하거나 서버 재접수에 성공할 때까지 미사용 자동 로그아웃을 미룹니다. 운영진은 타자 관리자 화면의 기기 백업 메뉴에서 이 JSON을 불러온 뒤 미전송 기록 접수로 저장할 수 있습니다. 복구 기록도 운영진 확인 전에는 검증 대기 상태입니다. 학생 소유 정보가 있는 기록은 관리자 재접수 후에도 원래 학생에게 귀속됩니다. 소유 정보가 없는 예전 기록은 임의로 학생 계정에 연결하지 않습니다.

관리자 전체 JSON은 업무 DB 백업입니다. 글·타자 기록·접수 키·문구·공개 글·학생 명부 및 제재·관리 이력·행사 및 세션 설정을 포함합니다. Firebase Auth 계정·비밀번호와 관리자 권한은 포함하지 않습니다. 행사 접수를 잠시 닫고 관리자 편집을 멈춘 뒤 내보내면 백업 도중 변경을 피할 수 있습니다.

백업 형식 v4에는 글 휴지통과 변경 이력도 포함합니다. 복원 도구는 기존 v2·v3도 읽습니다. 새 조회를 사용하려면 `db/firestore.indexes.json`과 `db/firestore.rules`를 함께 배포하고 인덱스 준비가 끝나야 합니다.

```text
node db/scripts/restore-backup.mjs --input PRIVATE_BACKUP.json --project PROJECT_ID --dry-run --admin-module-dir EXTERNAL_NODE_MODULES --report PRIVATE_REPORT.json
```

복원 도구는 기본적으로 읽기 전용 검사를 합니다. 같은 문서는 건너뛰고, 기존 내용과 다른 문서가 하나라도 있으면 복원을 시작하지 않습니다. 검토 후 `--apply`를 지정하면 누락 문서만 생성하며 기존 문서를 덮어쓰거나 삭제하지 않습니다. 일부 실패 후에는 같은 파일로 재실행할 수 있습니다. 다른 Firebase 프로젝트로 복원할 때는 `--allow-project-change`가 추가로 필요하며, Auth 계정과 관리자 권한은 별도로 준비해야 합니다. 입력·자격 증명·복원 보고서는 저장소 밖에 둡니다.

기존 명부 연결·학생 비밀번호 재발급 도구는 과거 자료용으로 보존하며 현재 행사 참가에는 필요하지 않습니다. Functions를 배포하거나 요금제를 바꿀 필요가 없습니다. 운영에 적용할 때는 먼저 접수를 닫고 새 `db/firestore.rules`를 `os20th`에 배포한 뒤 정적 파일을 GitHub Pages에 반영합니다. 규칙과 클라이언트를 함께 적용하지 않으면 새 방식 제출이 거부됩니다. 행사 당일 운영진 기기에서 관리자 로그인 → 접수 열기 → 참가·글 제출 → 검수·순위·공개 → 접수 마감을 확인합니다.

전체 명부, 검토 보고서, 자격 증명, 테스트, 설치 파일, 로그는 공개 저장소에 포함하지 않습니다.
