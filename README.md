# 행사 웹사이트

GitHub Pages + Firebase. 학생 화면은 HTML·CSS·JavaScript를 직접 수정하며 설치·빌드 과정이 없습니다.

- `typing/`: 학생 타자 대회. 관리자 `/typing/admin/`.
- `write/`: 학생 글 작성. 관리자 `/write/admin/`.
- `welcome/`: 승인된 공개 글 조회. 로그인 불필요. 관리자 `/welcome/admin/`.
- `db/`: Firebase 연결·DB 작업·학생 관리·공개 설정·보안 규칙·인덱스·관리 도구. 명부 자체는 포함하지 않습니다.

루트 `/`에는 페이지가 없습니다. 공통 파일은 루트에 둡니다.

Firebase 명령은 `db/`에서 실행하거나, 저장소 루트에서 `--config db/firebase.json`을 지정합니다. 운영 프로젝트는 명시적으로 선택합니다.

```text
firebase deploy --config db/firebase.json --project os20th --only firestore:rules,firestore:indexes
```

디자인은 `style.css`의 공통 색·테두리 변수와 기본 요소 스타일에서 조정합니다. 타자 입력 표시는 `typing/style.css`에 둡니다. 프레임워크·아이콘·외부 폰트 의존성은 없습니다.

| 파일                                                                  | 용도                                                    |
| --------------------------------------------------------------------- | ------------------------------------------------------- |
| `db/firebase.js`                                                      | 학생·관리자 인증, Firebase 연결, 세션 정책              |
| `login.js`                                                            | 학번·비밀번호 통합 로그인(관리자 이메일도 처리)         |
| `db/database.js`                                                      | 글·타자 접수, 검증, 검수·공개, 내보내기                 |
| `admin.js`, `db/students.js`                                          | 관리자 화면과 학생 검색·제한·관리 기록                  |
| `common.js`, `style.css`                                              | 공통 함수·스타일                                        |
| `db/firebase-config.json`                                             | 공개 웹 SDK 설정                                        |
| `db/firestore.rules`, `db/firestore.indexes.json`, `db/firebase.json` | 보안 규칙·인덱스·배포 설정                              |
| `db/scripts/import-students.mjs`                                      | 서버 Admin SDK를 사용하는 멱등 학생 일괄 등록           |
| `db/scripts/restore-backup.mjs`                                       | 비공개 DB 백업 검사·누락 문서 복원                      |
| `db/scripts/functions/`                                               | 관리자 전용 비밀번호 재발급 서버. 운영 연결은 현재 보류 |

로컬 실행: Node 24 이상에서 `node serve.mjs`. `/typing/`, `/write/`, `/welcome/`으로 접속합니다. `?emulator=1`은 localhost 또는 127.0.0.1에서만 에뮬레이터에 연결하며 기기 보호 정책을 바꾸지 않습니다.

학생 로그인 학번은 검증된 현재 5자리 학번입니다. Auth UID와 `students/{uid}` 문서 ID는 별도로 생성한 무작위 20자리 문자열입니다. 학생 문서의 `student_id`는 이 내부 UID와 같고, 화면에 표시하는 현재 학번은 `login_id`입니다. 내부 Auth 이메일은 `<현재 학번>@students.<Firebase projectId>.invalid`로 연결합니다. 현재 학번이 확인되지 않은 계정에는 UID 기반의 내부 이메일을 사용하며, 학번 연결 전에는 학생 로그인을 허용하지 않습니다. 7자리 입학번호로 로그인하는 방식은 지원하지 않습니다.

입학 당시 7자리 학번은 최초 비밀번호 설정에만 사용하며 UID·문서 ID·Firestore 필드에 저장하지 않습니다. 현재 번호 연결이나 계정 이전 때문에 비밀번호를 초기화하지 않습니다. 초기 비밀번호의 학번 규칙은 추측 가능하므로 계정 기록만으로 실제 작성자를 확정하지 않습니다. 별도 회원가입이나 최초 변경 강제는 없습니다. Firestore에는 비밀번호나 비밀번호 해시를 저장하지 않습니다.

5자리 로그인은 인증 후 명부의 `login_id`가 입력한 번호와 일치하는지도 검사합니다. 학생 로그인은 Firebase 인증과 `students/{uid}` 명부의 활성 상태를 확인합니다. 이름은 명부에서 읽습니다. 관리자 이메일은 기존 `admins/{uid}.enabled` 권한을 확인한 뒤 해당 기능의 관리자 화면으로 이동합니다. 학생 로그인 시 이전 관리자 세션은 종료합니다. 예전의 학번·이름 입력 세션과 익명 계정은 새 제출에 사용할 수 없습니다.

글과 타자 기록의 `owner_uid`는 인증 계정이며 타자 `participantId`·`displayName`은 명부의 학번·이름과 일치해야 합니다. 새 글은 승인 대기 상태입니다. 공개 글에는 기존 공개용 본문·별명만 포함하며 학생 명부와 관리 기록은 공개하지 않습니다. 기존 글·타자 기록을 지우거나 새 학생 계정에 자동 귀속하지 않습니다.

관리자 학생 탭에서 학번·이름·학년으로 검색하고 작성 제한, 기간 제한, 계정 활성 상태, 작성 글, 관리 기록을 확인합니다. 작성 제한은 글에만 적용하고, 비활성 계정은 학생 제출 전체를 거부합니다. 상태 변경은 사유와 불변 관리 기록을 같은 배치로 저장합니다. 현재 학년은 운영 설정의 기준 학년도와 고정 입학년도로 계산하고, 입학 학번으로 현재 반·번호를 추정하지 않습니다.

관리자 글·타자 목록은 DB 커서로 다음 페이지를 읽습니다. 글은 20건, 타자는 25건 단위입니다. 타자 순위는 선택한 문구·확인 상태 전체를 기준으로 계산하고 페이지를 넘겨도 순위·동점·학생별 최고 기록 기준을 유지합니다. 전체 시도는 접수 최신순입니다. 본문·이름 검색은 DB에서 읽은 후보를 확인하므로 검색 조건에 따라 추가 페이지를 읽을 수 있습니다. 전체 조회는 명시적인 CSV·JSON 내보내기와 백업에서 사용합니다.

글 목록에서 개별·선택 승인 및 제외가 가능합니다. 일괄 검수는 글별로 원문·공개 내용·이력을 함께 저장하며, 일부 실패하면 완료 건수를 알립니다. 삭제는 `letterTrash`로 이동하고 공개 내용은 즉시 제거합니다. 복원은 검토 대기로 돌아가며, 영구 삭제는 휴지통에서만 가능합니다. 접수 키와 변경 이력은 삭제하지 않습니다. `letterLogs`는 관리자 추가·수정·검수·휴지통 이동·복원·영구 삭제의 담당자·시각·변경 전후 내용을 보관하며 수정·삭제할 수 없습니다. 글별 이력과 전체 변경 이력에서 조회합니다. 기존 글은 소급 이력을 만들지 않습니다.

학생 탭에는 학번 연결·미연결 인원과 미연결 필터가 있습니다. 관리자 명부는 같은 세션에서 1분간 메모리에 재사용하고 새로고침으로 다시 읽습니다. 로그아웃·계정 전환·권한 해제 시 비웁니다. 관리자 권한 해제는 실시간으로 반영합니다. 공개 `welcome/`은 인증 SDK나 로그인 세션을 초기화하지 않고 공개 DB만 연결합니다.

`settings/sessionPolicy`는 관리자 설정에서 관리합니다. 없으면 공용 기기 모드·미사용 10분·2026학년도를 적용합니다. 공용 기기는 메모리 인증만 사용하고 글 제출 후 자동 로그아웃합니다. 개인 기기는 브라우저 탭 세션을 유지합니다. 정책은 URL로 해제할 수 없습니다. 타자 진행·저장 중에는 미사용 로그아웃을 미룹니다. 저장 실패 기록은 기기 백업에 남기고 로그아웃 시 학생 화면을 비웁니다. 기기 백업은 관리자 화면에서만 조회·재전송하며 다음 학생에게 이전 결과를 표시하지 않습니다.

글 저장 결과가 확인되지 않으면 같은 접수 번호와 내용을 유지해 재시도합니다. 이때는 미사용 자동 로그아웃을 미루고, 직접 로그아웃하거나 계정 권한이 해제되면 입력 내용을 비웁니다. 기간 제한이 끝난 글 작성 화면은 자동으로 다시 활성화됩니다.

모든 타자 시도는 보관합니다. 문구 버전·연습/공식별 학번당 최고 기록 하나에 순위를 매기며 점수 → 오타 → 소요 시간으로 비교합니다. 완전 동점인 같은 학생의 시도는 먼저 완료한 것을 대표로 선택합니다. 제외 기록은 순위에 반영하지 않습니다. 관리자 보기에서 최고 기록·전체 시도를 전환하고 CSV도 선택한 보기를 따릅니다. 전체 JSON은 모든 기록을 보관합니다. 시작·중단·다시 하기 버튼은 없습니다. 로그인 후 문구를 불러오면 첫 입력부터 측정합니다. 분당 타수는 글자 수가 아니라 두벌식 키 입력 수를 기준으로 계산합니다.

학생 일괄 등록은 공개 웹사이트에서 실행하지 않습니다. `firebase-admin`은 별도 개발 환경에 설치하고, 명부·자격 증명·결과 보고서는 저장소 밖에 둡니다. 비공개 입력은 `uid`(무작위 20자리), `admission_id`(입학번호), `student_name`, `admission_year`, 선택적인 `login_id`로 구성합니다. `uid`는 최초 준비 시 한 번 생성하고 재시도에도 같은 값을 사용합니다. 입학번호는 Auth 최초 비밀번호를 설정할 때만 사용하고 학생 문서·결과 보고서에 복사하지 않습니다. 도구는 입력 전체의 중복·형식·관리자 충돌을 검사하고 기본값으로 읽기 전용 검증을 수행합니다.

```text
node db/scripts/import-students.mjs --input PRIVATE_ROSTER.json --project PROJECT_ID --dry-run --admin-module-dir EXTERNAL_NODE_MODULES --report PRIVATE_REPORT.json
```

검토한 명부에 `--apply`를 명시해야 계정을 생성합니다. `--only 현재학번` 또는 `--only 내부UID`로 개별 재시도할 수 있으며 `--concurrency`는 기본 5, 범위 1~10입니다. Auth 생성 후 Firestore 생성이 실패한 경우 다음 실행에서 학생 문서만 복구합니다. 기존 계정 비밀번호·제재 상태·관리자 계정은 변경하지 않습니다. 현재 학번 연결은 `db/scripts/link-student-logins.mjs`에서 비공개 `{student_id: 내부UID, login_id: 현재학번}` 연결표와 `--academic-year`를 사용합니다. 중복·학년·기존 계정·번호 충돌을 전체 사전 검사한 후 `--apply`로 이메일과 로그인 번호만 연결합니다. UID·이름·비밀번호·제재 상태·기존 기록은 유지하고, Auth와 명부 사이의 부분 실패는 재실행으로 복구합니다. 기존 명부 등록 스크립트도 이미 연결된 로그인 번호를 보존합니다. 공개 로그인 번호 조회 컬렉션은 만들지 않습니다.

기본 인증은 Admin SDK의 Application Default Credentials이며, `--credential-module`로 저장소 밖의 자격 증명 모듈을 지정할 수 있습니다. 보고서에는 진행·오류를 남기고 비밀번호는 기록하지 않습니다.

기존 관리자 비밀번호 재설정은 Firebase 기본 이메일 링크를 사용합니다. 학생 비밀번호 재발급은 서버 Admin SDK가 필요합니다. `db/scripts/functions`는 관리자 권한을 확인하고 임시 비밀번호를 한 번만 반환하며 비밀번호를 로그·Firestore에 남기지 않습니다. 현재 무료 요금제 유지 방침에 따라 운영 배포는 보류했고 `studentAdminFunctionsEnabled`를 활성화하지 않습니다. 향후 서버 배포가 완료된 경우에만 이 공개 설정을 `true`로 바꿉니다. Functions 지역을 바꾸면 서버 `STUDENT_FUNCTION_REGION`과 클라이언트 `functionsRegion`을 같이 설정합니다. 학생 상태 관리에는 서버 함수가 필요하지 않습니다.

GitHub Pages는 `main` 브랜치 루트를 직접 배포하며 푸시하면 반영됩니다. 다른 레포·도메인으로 옮길 때 파일의 상대적인 구조를 유지하면 경로가 따라갑니다.

- `CNAME`은 임시 배포 전용이므로 새 저장소에서는 제거하거나 새 도메인으로 바꿉니다.
- 새 저장소의 Pages를 활성화하고 Firebase Authentication의 승인된 도메인에 새 호스트를 등록합니다.
- 같은 Firebase 프로젝트를 사용하면 기존 Auth 계정·DB·SDK 설정을 그대로 유지합니다. 다른 Firebase 프로젝트로 바꾸는 경우 Auth·DB 이전과 공개 SDK 설정 교체가 별도로 필요합니다.
- 보안 규칙은 대상 Firebase에 배포해야 적용됩니다. 익명 인증의 활성 여부와 관계없이 새 학생 제출은 규칙에서 차단합니다.

관리자 글 목록에는 작성 계정이 표시되며, 해당 학생 관리 화면으로 이동하면 문제 글이 관련 글로 선택됩니다. 이 정보는 공개 글에 포함되지 않습니다.

타자 기록의 서버 접수에 실패하면 기기 보관함에 남깁니다. 기기 보관도 실패했을 때만 기록 파일 저장 버튼을 표시하고, 파일 저장을 확인하거나 서버 재접수에 성공할 때까지 미사용 자동 로그아웃을 미룹니다. 운영진은 타자 관리자 화면의 기기 백업 메뉴에서 이 JSON을 불러온 뒤 미전송 기록 접수로 저장할 수 있습니다. 복구 기록도 운영진 확인 전에는 검증 대기 상태입니다. 학생 소유 정보가 있는 기록은 관리자 재접수 후에도 원래 학생에게 귀속됩니다. 소유 정보가 없는 예전 기록은 임의로 학생 계정에 연결하지 않습니다.

관리자 전체 JSON은 업무 DB 백업입니다. 글·타자 기록·접수 키·문구·공개 글·학생 명부 및 제재·관리 이력·행사 및 세션 설정을 포함합니다. Firebase Auth 계정·비밀번호와 관리자 권한은 포함하지 않습니다. 행사 접수를 잠시 닫고 관리자 편집을 멈춘 뒤 내보내면 백업 도중 변경을 피할 수 있습니다.

백업 형식 v4에는 글 휴지통과 변경 이력도 포함합니다. 복원 도구는 기존 v2·v3도 읽습니다. 새 조회를 사용하려면 `db/firestore.indexes.json`과 `db/firestore.rules`를 함께 배포하고 인덱스 준비가 끝나야 합니다.

```text
node db/scripts/restore-backup.mjs --input PRIVATE_BACKUP.json --project PROJECT_ID --dry-run --admin-module-dir EXTERNAL_NODE_MODULES --report PRIVATE_REPORT.json
```

복원 도구는 기본적으로 읽기 전용 검사를 합니다. 같은 문서는 건너뛰고, 기존 내용과 다른 문서가 하나라도 있으면 복원을 시작하지 않습니다. 검토 후 `--apply`를 지정하면 누락 문서만 생성하며 기존 문서를 덮어쓰거나 삭제하지 않습니다. 일부 실패 후에는 같은 파일로 재실행할 수 있습니다. 다른 Firebase 프로젝트로 복원할 때는 `--allow-project-change`가 추가로 필요하며, Auth 계정과 관리자 권한은 별도로 준비해야 합니다. 입력·자격 증명·복원 보고서는 저장소 밖에 둡니다.

현재 학번 미연결 계정은 최신 명부가 준비되면 연결합니다. 정식 저장소·도메인으로 이전하기 전에는 운영진 기기에서 로그인 → 글 검수·제한 → 타자 접수·재전송 → 백업 복원 흐름을 확인합니다. 학생 비밀번호 재발급 서버의 운영 배포는 무료 요금제 유지 결정에 따라 보류합니다.

전체 명부, 검토 보고서, 자격 증명, 테스트, 설치 파일, 로그는 공개 저장소에 포함하지 않습니다.
