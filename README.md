# 천안오성고등학교 20대 학생회 행사 웹사이트

GitHub Pages + Firebase 기반의 타자 대회·글쓰기 사이트입니다. HTML·CSS·JavaScript를 직접 실행하며 프런트엔드 설치·빌드 과정은 없습니다.

## 실행과 작업 브랜치

```sh
node serve.mjs 5176
```

- 학생: `/typing/`, `/write/`, `/welcome/`
- 관리자: `/typing/admin/`, `/write/admin/`, `/welcome/admin/`
- 작업·Pages 배포 브랜치: `design/obyeol-retro-grid` 루트. `main`을 수정하지 않습니다.
- Firebase 프로젝트: `os20th`, 기본 STANDARD 데이터베이스, 서울 리전.
- `?emulator=1`은 localhost/127.0.0.1에서만 작동합니다. Auth 9098, Firestore 8088을 사용하며 프로젝트는 `demo-ohsung`입니다.

## Firebase 구조

컬렉션·필드 이름은 Firebase 콘솔에서 역할을 알아보기 쉬운 한글로 저장합니다. UI와 타자 엔진은 기존 객체 형식을 사용하고, `db/store.js`가 저장 경계에서 변환합니다. 경로·필드의 단일 정의는 `db/schema.js`입니다.

```text
관리자/{Firebase Auth UID}
운영설정/행사
운영설정/세션
타자대회/기본
  문구/{문구ID}
  기록/{접수UUID}
  참여제한/{학번}
  접수확인/{접수UUID}
  기록증/{학번·이름조회키}
글쓰기/기본
  접수글/{접수UUID}
  공개글/{접수UUID}
  휴지통/{접수UUID}
  검수이력/{이력UUID}
  접수확인/{접수UUID}
```

과거 명부·제재 데이터가 포함된 백업을 복원할 경우에만 `보관자료/이전자료/학생명부`와 `학생제재이력`을 사용합니다. 현재 행사에서 학생 계정이나 명부는 조회하지 않습니다.

타자 기록은 `학번`, `이름`, `최종점수`, `분당타수`, `누적오타`, `소요시간밀리초`, `상품수령여부` 등으로 저장됩니다. 관리자 목록은 서버 저장 시각을 `MM/DD HH:mm` 형식으로 표시하며 확인 단계는 없습니다. 과거 `검수상태` 필드는 호환을 위해 보존합니다. 과거 UID 기반 기록은 `이전계정UID`, `이전참가자ID`로 구분하며 학번으로 추정하지 않습니다. 공개 글에는 학번·이름·내부 계정 정보를 복사하지 않습니다. 자세한 의미와 변경 위치는 [DB 관리 안내](docs/database.md)에 있습니다.

## 유지할 운영 규칙

- 학생은 학번·이름을 직접 입력합니다. 학생 회원가입·비밀번호·OAuth·명부 인증을 사용하지 않습니다. 관리자만 Firebase Authentication과 관리자 역할 문서를 사용합니다.
- 타자는 현장에서 운영하며 학번당 한 번 접수합니다.
- 점수는 `max(0, round(기준타수 × 60000 / 소요시간밀리초) − 누적오타 × 3)`입니다. 분당 타수는 두벌식 키 입력 수를 기준으로 계산합니다. 한글 조합 중 임시 오답은 빨간색으로 표시하되 확정 전에는 감점하지 않습니다.
- 타자 결과·접수 확인·학번별 참여 제한·기록증 사본은 원자적으로 생성합니다. 같은 접수UUID·같은 내용으로 재시도하면 원래 접수로 처리합니다. 관리자 삭제는 해당 결과·접수 확인·그 결과에 연결된 참여 제한과 기록증을 함께 제거합니다. 같은 학번·이름으로 다시 들어오면 기존 기록증과 입력이 잠긴 완료 화면을 보여 줍니다.
- 타자 기록의 점수·타수·오타·시간·참가 정보는 접수 후 변경할 수 없습니다. 관리자 검수와 상품 수령 상태만 수정합니다. 과거 점수는 재계산하지 않습니다.
- 저장 응답이 불확실하면 기기 보관함에 기록을 남깁니다. 실제 서버 확인 전에는 저장 완료로 표시하지 않습니다. 기존 기기 JSON은 그대로 가져올 수 있으며 관리자 복구도 검토 대기로 접수합니다.
- 글은 횟수 제한 없이 접수하며 본문은 공백을 제외한 내용이 있어야 합니다. 본문과 공개용 본문 각각 UTF-8 128 KiB 한도를 유지합니다. 학생은 접수 후 원문을 조회·수정·삭제할 수 없습니다.
- 승인한 글의 공개용 본문과 별명만 공개 글에 투영합니다. 휴지통 이동 시 공개본을 제거하며 복원은 검토 대기로 돌아갑니다. 변경 전후·작업자·시각은 수정 불가능한 검수 이력에 보관합니다.
- 타자 문구 삭제는 기존 기록을 지우지 않습니다. 글 휴지통과 문구 삭제는 별개입니다.
- 공용 기기 모드의 기본 미사용 시간은 10분입니다. 진행·저장·확인되지 않은 백업이 있을 때는 자동 퇴장을 미룹니다. 학생에게 기기를 넘기기 전 관리자는 로그아웃합니다.

## 조회·백업·배포

관리자 글은 20건, 타자는 25건씩 커서로 조회합니다. 최고 기록 순위는 점수 → 오타 → 소요 시간으로 비교하며 페이지를 넘겨도 유지합니다. 공개 목록에는 비공개 원문·참가자 정보가 포함되지 않습니다.

전체 JSON은 백업 v6이며 역할 문서·운영 설정·타자·글·휴지통·이력·분리된 접수 정보를 포함합니다. Firebase Auth 계정·비밀번호·토큰은 포함하지 않습니다. 복원 도구는 v2~v6를 읽어 새 경로로 복원하고, 기존 내용이 다르면 덮어쓰지 않습니다. 백업·자격 증명·이전 보고서는 저장소 밖에 둡니다.

```sh
firebase deploy --config db/firebase.json --project os20th --only firestore:rules,firestore:indexes
node db/scripts/restore-backup.mjs --input PRIVATE_BACKUP.json --project os20th --dry-run --admin-module-dir EXTERNAL_NODE_MODULES --report PRIVATE_REPORT.json
```

타자 저장 경로와 학번별 참여 키는 행사 날짜에 의존하지 않습니다. 기록의 실제 완료·저장 시각은 그대로 보존합니다.

스키마를 바꿀 때는 새 클라이언트, 보안 규칙, 인덱스, 이전 도구를 함께 갱신합니다. 기존 경로의 쓰기를 잠그고 비공개 백업 → 이전 → 문서별 대조 → 프런트엔드 전환 → 실제 조회 확인 → 기존 경로 정리 순서로 진행합니다. [이전 도구 안내](docs/db-migration.md)를 따릅니다.

입학식용 정적 공개본은 관리자에서 `letters.json`을 내려받아 `welcome/letters.json`에 넣으면 됩니다. 정적 파일이 있는 동안 공개 중단·수정도 파일 교체 후 재배포해야 합니다. 파일이 없을 때만 DB 공개 목록을 사용합니다. 공개 JSON 형식은 기존 v1을 유지합니다.

## 운영 전 확인

- 임시 관리자 Auth 계정과 해당 역할 문서를 삭제하고 정식 운영자 로그인·권한을 확인합니다. 임시 계정의 비밀번호를 저장소에 남기지 않습니다.
- 운영진 기기에서 관리자 로그인 → 문구 선택 → 타자·글 접수 → 검수·순위·공개 → 저장 실패 재시도까지 확인합니다.
- 실제 참가자의 본인 여부와 공식 순위·상품 지급은 현장에서 운영진이 확인합니다.

모바일 테스트는 현재 요청 범위에서 제외합니다. 데스크톱 회귀 검사와 실제 Firestore·Auth 에뮬레이터의 접수·삭제·공개·복원·권한 검사를 사용합니다.
