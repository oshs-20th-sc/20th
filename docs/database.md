# Firebase DB 관리 안내

스키마 버전 6. 관리용 이름은 한글로 저장하고 앱 객체의 호환성은 저장 경계에서 유지한다.

## 어디에서 찾는가

| Firebase 위치 | 담는 정보 |
| --- | --- |
| `관리자/{UID}` | 로그인 계정의 관리자 사용 여부. 비밀번호는 Firebase Authentication에서만 관리 |
| `운영설정/행사` | 선택 문구, 글 접수 허용, 공개 글 열람 허용 |
| `운영설정/세션` | 공용 기기 모드와 자동 퇴장 대기 시간 |
| `타자대회/기본/문구` | 문구 제목·본문·기준 타수 |
| `타자대회/기본/기록` | 참가자·점수·타수·오타·시간·상품 상태 |
| `타자대회/기본/참여제한` | 학번별 한 번 참여를 보장하는 연결 정보 |
| `타자대회/기본/접수확인` | 타자 저장 재시도를 구분하는 접수번호·내용 해시 |
| `글쓰기/기본/접수글` | 학번·이름·별명·원문·공개용 편집본·검수 상태 |
| `글쓰기/기본/공개글` | 공개해도 되는 승인 본문·별명만 담은 사본 |
| `글쓰기/기본/휴지통` | 삭제 전 원문 사본과 삭제 담당자·시각 |
| `글쓰기/기본/검수이력` | 추가·편집·검수·삭제·복원의 변경 전후·담당자·시각 |
| `글쓰기/기본/접수확인` | 글 저장 재시도를 구분하는 접수번호·내용 해시 |

`기본`은 날짜와 무관한 저장 구분자이며 학생 화면의 이름을 바꾸지 않는다. 타자대회와 글쓰기 부모 문서도 실제로 생성하여 콘솔에서 기능을 찾아 들어갈 수 있다.

## 타자 기록 필드

| 필드 | 뜻 |
| --- | --- |
| `문서ID` | 접수UUID. 문서 자체의 ID와 같음 |
| `참가방식` | `record`이면 학번·이름을 직접 입력한 현재 방식 |
| `학번`, `이름` | 현재 방식의 참가 정보 |
| `이전계정UID`, `이전참가자ID` | 과거 계정 기반 기록의 원래 식별자. 학번으로 간주하지 않음 |
| `문구ID` | 사용한 문구 문서의 ID |
| `소요시간밀리초` | 소요 시간. 1,000밀리초 = 1초 |
| `분당타수` | 두벌식 키 입력 수 기준 타수 |
| `누적오타` | 확정 입력에서 발생한 오타 수. 수정해도 감점은 유지 |
| `최종점수` | 해당 기록에 저장된 최종 점수. 이전 시 재계산하지 않음 |
| `완료시각` | 기존 ISO 문자열을 보존한 완료 시각 |
| `접수시각`, `검수시각` | Firestore Timestamp. 검수 전에는 검수시각이 null |
| `검수상태` | 과거 호환용 상태. 타자 관리자에 확인 단계는 없으며 기존 제외 기록은 보존 |
| `상품수령여부` | 상품 수령 상태. 사전 확인 없이 표시 가능하며 과거 연습·제외 기록은 수령 처리 불가 |
| `원본기록ID` | 관리자 복구로 중복 기록을 보존한 경우 원래 결과 ID |

글의 `검수상태`는 `pending` 검토 대기, `approved` 승인, `rejected` 제외다. 기존 상태 값과 시간 타입은 호환성과 접수 해시를 보존하기 위해 유지한다. 한글 필드명과 상태 표시 번역은 다른 역할이다.

## 관련 문서를 함께 다루는 이유

타자 기록·접수 확인·참여 제한은 같은 원자적 작업으로 생성·삭제한다. 다른 기록에 연결된 참여 제한은 삭제하지 않는다. Firebase 콘솔에서 기록 하나만 지우면 이 연결 조건을 우회하므로 관리자 화면의 기록 삭제를 사용한다.

글의 공개본·휴지통·검수이력은 각각 공개 정보 분리, 복원, 변경 추적을 담당한다. 하나로 합치면 비공개 참가자 정보를 공개하거나 삭제 이력을 잃기 쉽다. 글 관리 화면에서 승인·휴지통·복원을 수행하면 관련 문서를 함께 처리한다.

## 코드 변경 위치

경로·필드는 `db/schema.js`, SDK 연결과 객체 변환은 `db/store.js`, 업무 동작은 `db/database.js`에서 수정한다. 필드 추가·경로 변경 시 보안 규칙, 인덱스, 백업·이전·복원 도구와 실제 에뮬레이터 검사를 함께 수정한다. 앱 내부 객체 이름만 고치려고 입력 엔진·기기 백업 형식을 바꾸지 않는다.

운영 전 임시 관리자 계정은 Firebase Authentication 계정과 `관리자/{UID}` 역할 문서를 모두 삭제한다. 정식 운영자의 권한을 먼저 확인하고 임시 계정을 제거한다. 비밀번호는 이 문서나 소스 코드에 저장하지 않는다.

## 재방문자의 타자 기록증

`타자대회/기본/기록증/{조회키}`는 완료 화면을 다시 보여주기 위한 최소 사본이다. 학번·이름, 최종 점수·타수·오타·소요 시간, 완료 시각과 당시 문구 사본만 담으며 계정 UID·접수 해시·내부 검수 정보는 넣지 않는다. 정상 접수는 기록·접수 확인·참여 제한과 이 사본을 같은 배치로 생성한다. 관리자 기록 삭제 시 연결된 기록증도 함께 지워 재참여할 수 있다.

조회키는 정규화한 학번 + 줄바꿈 + 이름의 SHA-256 소문자 hex다. 전체 목록은 관리자만 읽고, 학생은 정확한 조합의 기록증 하나만 읽는다. 이는 현재의 학번·이름 직접 입력에 맞춘 조회 방식이며 본인 인증 수단은 아니다. 기존 비공개 타자 기록과 참여 제한의 학생 조회 권한은 열지 않는다.

재방문 시 조회가 성공하면 저장된 점수와 문구로 완료 화면을 복원하고 입력을 잠근 뒤 기록증을 자동으로 연다. 새 기록을 생성하거나 다시 저장하지 않는다. 조회가 실패하면 입력을 열지 않고 다시 확인하도록 하며, 저장 실패·기기 백업·재시도 동작은 유지한다. 기록증에서는 저장 성공 안내를 생략하고, 저장 중·실패 안내만 보여 준다. 완료 화면의 저장 상태 표시는 유지한다.

기존 공식 기록은 `db/scripts/backfill-typing-certificates.mjs`로 기록증 사본만 추가한다. 기본값은 읽기 전용 계획이며, 저장소 밖의 비공개 백업이 필요하다. `--apply` 시 원본·참여 제한·문구·목적지를 트랜잭션에서 다시 확인하고 비어 있는 목적지만 생성한다. 기존 기록·점수·참여 제한은 수정하지 않는다. 과거 UID 기록과 다른 결과에 연결된 관리자 복구 중복은 자동 연결하지 않는다. 도입 전 기록은 당시 문구 사본이 없으므로 현재 남아 있는 문구로 복원하되, 점수·타수·오타·시간은 원본 값을 그대로 보존한다.

관리자 타자 목록의 일시는 서버 `접수시각`을 우선 사용하고, 없는 과거 기록만 `완료시각`을 사용한다. 한국 시각으로 `MM/DD HH:mm`만 표시한다. 조회·검수 필드 보존은 과거 데이터 호환용이며 행사일을 바꿔도 DB 경로나 참여 키를 수정할 필요가 없다.
